# 🏗️ Блок 6. Чистая архитектура и CQRS для системы пользователей

## 🎯 Общее описание
Реализуйте систему управления пользователями с использованием принципов Clean Architecture, CQRS и MediatR. Создайте поддерживаемое и тестируемое приложение с четким разделением ответственности и правильным управлением зависимостями.

**Стек:** .NET 8, Clean Architecture, CQRS, MediatR, PostgreSQL.

---

## 📋 Задачи

### 🏗️ Задача 1: Создание многослойной структуры проекта

1. **Уже созданы 4 отдельных проекта** в одном решении:
    - `Domain` - ядро системы
    - `Application` - бизнес-логика
    - `Infrastructure` - работа с данными
    - `Web` - Web API

2. **Настройте зависимости** между проектами так, чтобы:
    - Domain не зависит ни от чего
    - Application зависит только от Domain
    - Infrastructure зависит от Application и Domain
    - API зависит от всех остальных проектов

### 🔄 Задача 2: Доменная модель и репозиторий

1. **Создайте в Domain проекте сущность `User`** со свойствами:
    - `Id` (Guid)
    - `Email` (string, уникальный)
    - `FirstName` (string)
    - `LastName` (string)
    - `DateOfBirth` (DateTime)
    - `RegistrationDate` (DateTime)
    - `IsActive` (bool)

2. **Создайте интерфейс `IUserRepository`** в Domain проекте с методами:
    - `GetByIdAsync(Guid id)`
    - `GetAllAsync()`
    - `AddAsync(User user)`

3. **Реализуйте репозиторий в Infrastructure** с использованием EF Core и PostgreSQL (для упрощения можно использовать статические данные, как в блоке 4).

### 📦 Задача 3: Команды и запросы с MediatR

1. **Установите и настройте MediatR** во всех необходимых проектах.

2. **Создайте в Application проекте следующие команды и запросы**:

   **Команды:**
    - `CreateUserCommand`
    - `ActivateUserCommand`

   **Запросы:**
    - `GetUserByIdQuery`
    - `GetAllUsersQuery`

3. **Реализуйте обработчики (Handlers)** для каждого запроса и команды.

4. **Настройте маппинг** между сущностями и DTO с помощью AutoMapper.

### 🎯 Задача 4: Контроллеры и API

1. **Создайте контроллер `UsersController`** в API проекте со следующими endpoints:

   ```
   GET    /api/users             - получить всех пользователей
   GET    /api/users/{id}        - получить пользователя по ID
   POST   /api/users             - создать пользователя
   PATCH  /api/users/{id}/activate   - активировать пользователя
   ```

2. **Сделайте контроллеры тонкими** - они должны только:
    - Принимать HTTP запросы
    - Отправлять команды/запросы через MediatR
    - Возвращать HTTP ответы

### 🧪 Задача 5: Тестирование архитектуры

**Напишите модульные тесты** для:
   - Команд и запросов (MediatR handlers)

### 🛠️ Задача 6: Настройка DI и конфигурации

1. **Создайте классы настройки** (Extension methods) для каждого слоя:
    - `DomainServiceCollectionExtensions`
    - `ApplicationServiceCollectionExtensions`
    - `InfrastructureServiceCollectionExtensions`

2. **Настройте DI контейнер** в Program.cs:
   ```csharp
   builder.Services
       .AddDomain()
       .AddApplication()
       .AddInfrastructure(builder.Configuration);
   ```

3. **Вынесите строки подключения** в appsettings.json и используйте User Secrets для разработки.

4. **Настройте миграции EF Core** и обеспечьте автоматическое применение при запуске.

## 📚 Основные концепции

### Clean Architecture
- Принцип зависимостей (зависимости направлены к центру)
- Разделение на слои: Domain → Application → Infrastructure → Presentation
- Независимость бизнес-логики от внешних зависимостей

### CQRS (Command Query Responsibility Segregation)
- Разделение операций чтения и записи
- Команды (Commands) - изменяют состояние
- Запросы (Queries) - только чтение данных

### MediatR
- Паттерн "Посредник" для обработки команд и запросов
- Уменьшение связанности между компонентами

### Управление зависимостями
- Принцип инверсии зависимостей (DIP)
- Внедрение зависимостей через конструктор
- Использование интерфейсов для абстракции
